# magic-boto

> A Magic: The Gathering data backend and toolbox — card search, inventory tracking, AI-powered oracle tags, and a Model Context Protocol (MCP) server for LLM-native workflows.

Point your MCP-capable client (Claude Desktop, Cursor, etc.) at `http://localhost:8765/mcp` and ask it to build you a deck.

---

## What it does

| Feature | Where |
|---|---|
| Full-text card search with filters (color, type, keyword, set…) | HTTP + MCP |
| MTG editions/set catalog | HTTP + MCP |
| Personal card inventory (CSV in, query out) | HTTP + MCP |
| Oracle tag system — AI-generated semantic labels for cards | HTTP + MCP |
| Bulk tag sweep & audit powered by Claude | `invoke generate.*` |
| OpenAPI docs at `/docs` | HTTP only |
| MCP Inspector for debugging tool calls | Docker only |

The whole catalog comes from [MTGJSON](https://mtgjson.com). Tags are generated by Claude and stored in Postgres alongside the card data.

---

## Stack

- **Python 3.11+** — FastAPI · SQLAlchemy 2 · asyncpg · FastMCP · Alembic
- **Postgres 16** — primary data store (`magic_boto` schema)
- **Docker Compose** — full stack in one command
- **Anthropic SDK** — Claude for oracle tag generation/audit
- **Invoke** — task runner for every workflow

## Quick start

### 1. Environment

```powershell
# from repo root
Copy-Item .env.example .env
# fill in Postgres vars; ANTHROPIC_API_KEY only needed for tag generation
. .\load-env.ps1   # dot-source — do NOT run as a subprocess
```

> The dot (`. `) is required. Running `.\load-env.ps1` directly won't export vars into your shell.

### 2. Run

**Full stack (recommended):**
```bash
docker compose up
```

Services:
| Service | URL |
|---|---|
| HTTP API + OpenAPI docs | `http://localhost:8000/docs` |
| MCP Streamable HTTP | `http://localhost:8765/mcp` |
| MCP Inspector UI | `http://localhost:6274` |

**Local dev (hot-reload, Postgres in Docker):**
```powershell
cd tools_api
uv run invoke serve.local
```

### 3. Load the card catalog

```powershell
cd tools_api
uv run invoke migrate          # apply DB schema
uv run invoke fetch            # download & ingest MTGJSON (~5 min first run)
```

## Common workflows

All commands run from `tools_api/`.

### Database

```powershell
uv run invoke migrate              # apply pending migrations
uv run invoke migrate.down         # rollback one step
uv run invoke migrate.create       # create a new migration (prompts for name)
uv run invoke generate.db-schema   # regenerate debug/schema.sql from live DB
```

### Inventory

```powershell
uv run invoke import.inventory     # import a CSV
uv run invoke export.inventory     # export to CSV
uv run invoke delete.inventory     # wipe an inventory
```

### Oracle tags (requires `ANTHROPIC_API_KEY`)

```powershell
uv run invoke generate.tags --tag <name>        # sweep with Claude (bulk)
uv run invoke generate.audit-tags --tag <name>  # audit results with Claude Opus
```

### Lint, type-check

```powershell
uv run ruff check . --fix
uv run ruff format .
uv run mypy app tasks --no-incremental --cache-dir=nul
```

## MCP client setup

Connect any MCP-capable client to:

```
http://<host>:<TOOLS_MCP_PORT>/mcp
```

Default port is in `.env` / `docker-compose.yml` (`TOOLS_MCP_PORT`, default `8765`). Use the MCP Inspector at `http://localhost:6274` to explore available tools before wiring up a client.

For deck-building and inventory workflows, see [`tasks/deck-building/AGENTS.md`](tasks/deck-building/AGENTS.md).

## Development notes

- **No auto `.env` loading** — the app reads from the environment, not `.env` directly. Load it first.
- **Commit pattern** — services never call `commit()`; only the route/tool handler does.
- **MCP-only flows** — deck building and inventory edits should go through MCP tools, not raw SQL.
- **Windows-first** — scripts use PowerShell; paths use forward slashes in Python.
